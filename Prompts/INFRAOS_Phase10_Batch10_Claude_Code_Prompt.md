### 4.3 Retrieval pipeline (Step 115) — `apps/api/src/modules/ai/rag/`
`rag.service.ts` orchestrates these pure/testable stages (`scope.ts`, `retrieve.ts`, `hydrate.ts`, `rerank.ts`, `context.ts`, `redact.ts`, `injection.ts`, `grounding.ts`, `fallback.ts`):
1. **Validate & rate-limit:** strict zod (`question` 3–600 chars, trimmed, control chars stripped; `scope`; `threadId?`; `language?`), per-user limit (default 20 AI requests / 10 min, existing rate-limit middleware) + in-flight duplicate prevention (same user+question+scope hash within 10 s → return the in-flight/last result), daily budget gate (`AI_CHAT_DAILY_TOKEN_BUDGET`, Asia/Colombo day, from `aiUsageRecords`) → `429 AI_BUDGET_EXCEEDED` with a clear message. Requires `document.ask`; `AI_PROCESSING_ENABLED` and `AI_BASE_URL` configured else `503 AI_UNAVAILABLE` (with the fallback below).
2. **Scope → allow-list (server-side):** `DOCUMENT` / `DOCUMENTS` (≤ 20 ids, each must pass `documentAccess`) / `PROJECT` (project in scope; its ACTIVE, AI-ready documents) / `ALL` (the caller's accessible ACTIVE AI-ready documents, **newest 500**, `truncatedScope` flagged). Compute `coverage`: documents in scope vs searched vs **not AI-ready** (pending/failed/unsupported/scanned/excluded) — returned to the UI so users know what was *not* searched. Empty allow-list → `INSUFFICIENT_EVIDENCE` with the coverage explanation (no LLM call).
3. **Query preparation (no extra LLM call):** normalise; for short/anaphoric follow-ups ("and the penalty?", `<` 5 words or pronoun-led) prepend the previous question of the same thread for **retrieval only**; keep the user's original question for the prompt.
4. **Vector search:** FastAPI `/v1/search` with the allow-list, `topK = RAG_TOP_K` (default 24).
5. **Hydrate + re-authorise:** load chunks from MongoDB by `chunkId`; **drop** any hit that is not `status:"ACTIVE"`, whose `versionNo !== document.aiIndex.indexedVersionNo`, whose document is no longer accessible/ACTIVE/AI-allowed, or that Mongo can't find (stale vector) — count them in `retrieval`. Missing/zero survivors → INSUFFICIENT_EVIDENCE.
6. **Hybrid rerank (pure TS, no new infra):** over the ≤ 24 survivors compute a lexical score (BM25-lite on normalised tokens: lowercase Latin, NFC Sinhala/Tamil, keep numbers/clause tokens like `4.2`, `LKR`, `Rs.`) and combine `finalScore = 0.7·denseNorm + 0.3·lexNorm` (weights in one constants block); exact clause/number matches get a small bonus. Enforce a per-document cap (default 4 chunks/doc) for multi-document scopes.
7. **Evidence gate:** apply `RAG_MIN_SCORE` (env; **calibrated, not guessed** — see §4.10 `ai:calibrate-retrieval`; until calibrated use a conservative default and say so in the report). If the best chunk is below the gate → `INSUFFICIENT_EVIDENCE` (no LLM call, saves cost) with the **closest passages shown as "Related but not conclusive"** (labelled, optional).
8. **Context assembly:** keep the top `RAG_CONTEXT_CHUNKS` (default 8) plus **neighbour expansion** (±1 chunk of the same version for the top 3, to repair clause splits; mark `wasNeighbor`), de-duplicate, order by document then chunk order, cap total characters (`RAG_CONTEXT_MAX_CHARS`, default 12 000). Number sources `[1..n]`.
9. **Minimise (BR-AI-006):** deterministic **redaction** of Sri Lankan NIC numbers (old `\d{9}[VvXx]`, new `\d{12}`), email addresses and phone numbers in the context text **before** sending to the provider (config `AI_REDACT_CONTEXT`, default on; count in `retrieval`). Verification (§4.5) runs against the **redacted** text the model saw; stored quotes are therefore redacted text (UI notes it). Never send document file names, uploader names or internal ids to the model — only `title`, `category` and the source number.
10. **Injection screen (§4.6):** flagged chunks are excluded from context and counted (`flaggedSuspicious`); if exclusion leaves nothing → INSUFFICIENT_EVIDENCE with a neutral notice.
11. **Generate:** FastAPI `/v1/llm/answer` (§4.4) → raw structured output + usage.
12. **Verify & persist:** `grounding.ts` (§4.5) → final status/evidence; write `aiInteractions` + `aiUsageRecords` + audit; return the response DTO.
13. **Fallback ladder (never fake):** provider/model failure or invalid output after repair → if retrieval succeeded return `status: PASSAGES_ONLY` with up to 5 verbatim passages (title, pages, section, ≤ 400-char excerpt) labelled **"AI answer unavailable — relevant passages only"**; if retrieval also failed → `503` with `AI_UNAVAILABLE` and a pointer to DocTrace search. No path returns invented text.

### 4.4 LLM layer (FastAPI) — `apps/ai-service/app/llm/` + `prompts/`

### 4.5 Grounding verification (Express, pure + heavily unit-tested) — `grounding.ts`
Inputs: model output, the exact context chunks sent (redacted text), numbering map. Steps:
1. **Schema + id check:** drop citations whose `n` isn't a sent source; claims referencing unknown `n` lose those refs.
2. **Quote verification:** normalise both sides (NFC, collapse whitespace, unify quotes/dashes, strip zero-width **except** ZWJ/ZWNJ) and test that the quote is a contiguous substring of the cited chunk's text; verified → `quoteVerified:true` (store the quote, ≤ 240). Not verified → keep the **chunk-level reference** but `quoteVerified:false`, drop the quote text, and mark the UI state "excerpt not verified".
3. **Claim support:** a claim with no remaining valid citation → `supported:false` and is **excluded from the answer text shown as fact** (shown under "Unsupported statements removed: N" in the evidence panel, not in the body). If every claim is removed → `INSUFFICIENT_EVIDENCE`.
4. **Numeric/date grounding check:** extract amounts, percentages, dates and durations from the answer text (regex incl. `LKR`, `Rs.`, `%`, ISO/long dates, "90 days"); each must appear (normalised digits/separators) in a cited quote or cited chunk; otherwise add to `unverifiedFigures[]` and downgrade evidence to `PARTIAL`. Do not "fix" numbers.
5. **Evidence level:** `VERIFIED` (all quotes verified, no unverified figures, no dropped claims) · `PARTIAL` (some downgrades) · `NONE` (answer text withheld → INSUFFICIENT_EVIDENCE).
6. Final status: model `ANSWERED` + `VERIFIED` → `ANSWERED`; any downgrade → `PARTIAL` (UI shows the reasons); model `INSUFFICIENT_EVIDENCE` → keep it (never override to answered).
Return the DTO with `n`-numbered inline markers in `answer.text` (e.g. `…within 90 days [1][3]`) built **server-side** from verified claims — the model's own prose is not rendered directly if claims were removed.

### 4.6 AI safety controls (Step 115G, mandatory)
- **Prompt injection:** (a) context delimiters + random per-request token; (b) heuristic **injection screen** on chunks (patterns such as "ignore (all|previous) instructions", "system prompt", "you are now", "disregard", role-tag markers, long base64 blocks, and instructions addressed to "the AI/assistant/model" in en; include a small Sinhala/Tamil phrase list only if you can verify the translations; list uncertainty in the report) → flagged chunks excluded + counted; (c) no tools, no URLs rendered, output is plain text with server-built citation markers (**no markdown rendering of model text; links are never auto-linked**) — blocks exfiltration via image/URL; (d) output schema validation and grounding verification; (e) documents are never concatenated into the *system* message.
- **Cross-agency isolation:** allow-list + re-authorisation (§1.3); citations and quotes are **re-authorised on every read** of an interaction (if the user lost access or the document is archived/restricted/deleted, the citation shows "No longer accessible" and the stored quote is hidden).
- **Sensitive content:** SENSITIVE/AI-excluded documents are never indexed (Batch 09), so never retrieved; redaction per §4.3.9; no export of full chunk text beyond cited quotes and the Batch 09 chunk-preview (separately permissioned).
- **Abuse/cost:** rate limits, budget gate, input caps, output token caps (`AI_QA_MAX_OUTPUT_TOKENS` default modest), per-user concurrency 1, abort handling (client abort cancels the upstream call).
- **Safe errors:** codes only (`AI_UNAVAILABLE`, `AI_TIMEOUT`, `AI_BUDGET_EXCEEDED`, `AI_RATE_LIMITED`, `AI_INVALID_OUTPUT`, `SCOPE_EMPTY`, `FORBIDDEN_SCOPE`), never provider bodies or stack traces.
- **Transparency:** every AI response is labelled AI-generated, shows model name (from env), prompt version and evidence level; a persistent "AI can make mistakes — verify against the cited sources" note; BR-AI-001: no "approve/reject/decide" affordances anywhere.

### 4.8 Structured information extraction (Step 118)
**Schema registry** (`extraction-templates.ts`, typed, shared with web): `PROJECT_BASICS` (project name, location(s), implementing agency), `CONTRACT_KEY_TERMS` (contractor name, contract number, **contract value** `{amountText, currency}`, contract date, commencement date, completion date or period, defects-liability period, retention %, performance security, liquidated-damages terms, payment terms), `FINANCIAL_FIGURES` (labelled amounts), `MILESTONES` (name, planned date, deliverable), `OBLIGATIONS` (party, obligation, deadline), `APPROVAL_DETAILS` (approving authority, reference no., date, conditions), `INSPECTION_FINDINGS` (finding, severity if stated, location, recommended action, date), `RISKS_ISSUES` (stated risks/issues). Each field `{ key, label, type: STRING|DATE|MONEY|PERCENT|DURATION|LIST|ENUM, repeats? }`.
**Extraction run:** per field-group, Express retrieves with template-defined queries against the single document (`allowList=[docId]`), or passes the whole document when it has ≤ ~12 chunks; FastAPI `/v1/llm/extract` returns, per field: `{ status: FOUND | NOT_FOUND | AMBIGUOUS, rawText, citations:[{n, quote}] }` — **the model returns the text as written in the document; it must not compute or convert.** **Express normalises deterministically:** dates via a strict parser (ISO, `DD/MM/YYYY`, long English forms; ambiguous formats → AMBIGUOUS with both readings listed), money via a parser → `{ amountMinor (integer cents), currency }` only when the quote unambiguously contains it (LKR/Rs./USD; else keep text), percentages, durations. **A value is accepted as `FOUND` only if its raw text appears in a verified quote;** otherwise → `AMBIGUOUS`/`NOT_FOUND` with reason. **No numeric confidence percentages** — show `evidenceStrength`: `STRONG` (verified quote), `WEAK` (chunk-level only), `NONE`.
**Diff against authoritative records (read-only, scope-checked):** if the document is linked to a project/contractor/payment/asset, compute per field `current` vs `extracted` → `MATCH | DIFFERS | NO_RECORD | NOT_COMPARABLE` (e.g. contract value vs the project's budget/contract fields; dates vs project dates; contractor name normalised-compare vs the assigned contractor; project name vs title). Only compare with records the viewer may read (per-source permission tiering; finance values only with finance permission). Comparison is informational; **mismatches are flagged, never auto-resolved.**
**Human review (required):** artifact `review` holds per-field decisions (Accept / Edit (typed value validated by the same parser) / Reject), by users with `document.update` (or the `document.ask` requester for their own view-only notes? **No** — decisions are shared and require `document.update`); progress counter; "Accept all strong matches" helper (explicit confirm; only `STRONG`+`FOUND`+not `DIFFERS`).
**What "apply" means in this batch (BR-AI-001/002):** **no write to Project, finance, contractor, inspection or asset records.** Allowed: (a) **Apply to document metadata** — accepted/edited values may populate DocTrace's own fields via the existing `PATCH /documents/:id` flow: `reference`, `documentDate`, `expiresAt`, `title` suggestion, `tags` (a small, explicit mapping table; confirmation dialog shows before/after; audited `ai.extraction_applied_to_metadata` with field names only); (b) **Copy value** and **Open the related record** deep links so the user performs the official change through the module's own (approval-gated) workflow. State this plainly in the UI.
**API:** `GET /documents/:id/ai/extractions` (artifacts + template catalog), `POST /documents/:id/ai/extractions` `{template, regenerate?}` (async artifact like §4.7), `GET /documents/:id/ai/extractions/:artifactId` (fields, diffs, review state), `PUT /documents/:id/ai/extractions/:artifactId/review` `{ decisions: [{ fieldKey, decision, editedValue? }] }` (`document.update`, OCC `version`), `POST …/apply-metadata` `{ fieldKeys[] }` (`document.update`).
